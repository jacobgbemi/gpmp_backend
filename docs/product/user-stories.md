# GlintPM Private --- User Stories

## 1. Purpose

User stories describe desired user outcomes from the perspective of the
people using or managing the product.

They are working product requirements and should be refined as customer
discovery and implementation progress.

## 2. Project Setup

### US-001 --- Create Project

**As a Project Manager,** I want to create a project with essential
project information so that the project can be managed within the
system.

**Acceptance criteria:** - Required project information is validated. -
A unique project identifier is created. - Unauthorized users cannot
create projects. - Creation is recorded for audit purposes where
applicable.

### US-002 --- View Project

As an authorized user, I want to view project information so that I
understand the current project context.

### US-003 --- Update Project

As an authorized user, I want to update permitted project information so
that project records remain current.

------------------------------------------------------------------------

## 3. Planning and Scheduling

### US-004 --- Record Planning Information

As a Planner, I want to record or import relevant planning information
so that the project schedule can support project control.

### US-005 --- Establish Baseline

As an authorized project-controls user, I want to establish an approved
baseline so that actual performance can be compared against an approved
plan.

### US-006 --- Compare Plan and Actual

As a Planner, I want to compare planned and actual performance so that I
can identify schedule variance.

------------------------------------------------------------------------

## 4. Progress

### US-007 --- Record Progress

As a project team member, I want to submit project progress so that
project status reflects current field information.

### US-008 --- Review Progress

As a Project Manager, I want to review submitted progress before relying
on it for reporting.

### US-009 --- Identify Progress Variance

As a Project Controls Manager, I want to identify significant progress
variance so that corrective action can be considered.

------------------------------------------------------------------------

## 5. Cost Control

### US-010 --- Record Budget

As a Cost Engineer, I want to record approved budget information so that
project cost performance can be monitored.

### US-011 --- Record Actual Cost

As an authorized user, I want to record or import actual cost
information so that project financial performance can be monitored.

### US-012 --- Forecast Cost

As a Cost Engineer, I want to maintain a project cost forecast so that
management can understand potential final cost.

### US-013 --- Analyze Cost Variance

As a Project Manager, I want to understand cost variance and its drivers
so that corrective action can be taken.

------------------------------------------------------------------------

## 6. Risks and Issues

### US-014 --- Record Risk

As a Project Manager, I want to record project risks so that threats can
be monitored.

### US-015 --- Assign Risk Owner

As a Project Manager, I want to assign responsibility for a risk so that
ownership is clear.

### US-016 --- Track Issue

As a project team member, I want to record and track issues so that
unresolved problems remain visible.

------------------------------------------------------------------------

## 7. Changes and Variations

### US-017 --- Record Change

As an authorized user, I want to record a project change so that its
effect can be tracked.

### US-018 --- Track Change Status

As a Project Manager, I want to track the approval status and impact of
a change.

------------------------------------------------------------------------

## 8. Reporting

### US-019 --- Generate Project Report

As a Project Manager, I want to generate a project report so that
stakeholders can understand project performance.

### US-020 --- View Dashboard

As an executive, I want a concise dashboard so that I can focus on
important project exceptions.

### US-021 --- Trace Report Data

As a Project Controls Manager, I want important reported values to be
traceable to underlying records so that reporting can be trusted.

------------------------------------------------------------------------

## 9. Accountability

### US-022 --- Assign Action

As a Project Manager, I want to assign an action to a responsible person
so that follow-up is clear.

### US-023 --- Track Decision

As a Project Manager, I want to record important project decisions so
that the project history is preserved.

### US-024 --- Track Overdue Actions

As a Project Manager, I want to see overdue actions so that unresolved
issues receive attention.

------------------------------------------------------------------------

## 10. AI-Assisted Capabilities --- Future Direction

### US-025 --- Identify Exceptions

As a Project Controls Manager, I want the system to identify unusual or
concerning project trends so that I can investigate them.

### US-026 --- Explain Variance

As a Project Manager, I want AI-assisted explanations of project
variance based on available project data so that I can investigate
potential causes faster.

### US-027 --- Summarize Reporting Period

As a Project Manager, I want the system to summarize important changes
during a reporting period so that I can review project status
efficiently.

AI-generated analysis should be treated as decision support and should
not silently modify authoritative project records.

## 11. Story Refinement

Every story should eventually have:

-   Acceptance criteria
-   Priority
-   Dependencies
-   Security considerations
-   Test cases
-   Definition of done
