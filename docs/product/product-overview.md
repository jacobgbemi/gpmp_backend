# GlintPM Private --- Product Overview

## 1. Product Summary

GlintPM Private is a proposed project-controls technology platform
designed to help project-based organizations gain better visibility,
control, and accountability across project planning, progress, cost,
risk, reporting, and decision-making.

The product is intended to combine GlintPM's project-controls expertise
with software and automation.

The working product principle is:

> **Better project data → better project visibility → better decisions →
> better project control.**

This document describes the current product direction. Features marked
as proposed or planned should not be treated as implemented
functionality until verified in the repository.

## 2. Problem Being Addressed

Project-based organizations often have project information distributed
across spreadsheets, Primavera P6/MS Project files, emails, documents,
messaging platforms, accounting records, and individual team members.

This can make it difficult to answer basic management questions quickly
and reliably:

-   What was planned?
-   What has actually happened?
-   What has changed?
-   What is causing the variance?
-   What is the current forecast?
-   Which risks require attention?
-   Which decisions are overdue?
-   Who is responsible for the next action?
-   Can the reported numbers be traced back to their source?

GlintPM Private aims to create a structured control layer around this
information.

## 3. Product Vision

Build a trusted digital project-controls environment where project teams
can manage, connect, analyze, and communicate project information from a
common source of truth.

## 4. Product Mission

Help project-based companies move from fragmented project information
and reactive reporting toward structured, traceable, data-driven project
control.

## 5. Core Product Areas

The initial product direction may include:

-   Project portfolio and project setup
-   Project planning and scheduling
-   Baseline management
-   Progress measurement
-   Cost monitoring
-   Schedule and cost variance
-   Forecasting
-   Risk and issue tracking
-   Change/variation tracking
-   Project reporting
-   Dashboards and management visibility
-   Documents and supporting evidence
-   Auditability and accountability
-   Automation and, where appropriate, AI-assisted analysis

The exact MVP scope should be validated against the repository and
product requirements before implementation is considered complete.

## 6. Intended Product Differentiation

GlintPM Private is not intended to be simply another generic
task-management application.

Its differentiation is expected to come from combining:

1.  Project-controls domain knowledge
2.  Structured project data
3.  Engineering discipline
4.  Automation
5.  Analytics and reporting
6.  Eventually, AI-assisted project intelligence

## 7. Product Principles

### Domain-first

Project-controls methodology should drive the software design, rather
than adding project-controls terminology to a generic application.

### Data integrity first

Important project information should be structured, validated,
traceable, and protected against accidental corruption.

### Human accountability

Automation and AI may assist users, but accountable project decisions
remain with authorized people.

### Evidence over assumptions

Important project metrics and decisions should be traceable to
underlying records where practical.

### Incremental development

Build and validate the foundation before adding unnecessary complexity.

### Engineering ownership

AI may assist with implementation, but humans own architecture,
requirements, security, testing, and production behavior.

## 8. Current Product Status

**Status:** Product/MVP under active development.

The exact implementation status of each capability should be maintained
in the repository's engineering documentation and verified against the
source code.

## 9. Success Indicators

Potential product-level indicators include:

-   Reduced time required to prepare project reports
-   Faster identification of project exceptions
-   Improved visibility of schedule and cost variance
-   Improved traceability of project information
-   Reduced dependence on disconnected spreadsheets
-   Increased accountability for actions and decisions
-   Increased adoption by project-based organizations
-   Measurable reduction in manual reporting effort

These are proposed indicators, not current measured outcomes.
