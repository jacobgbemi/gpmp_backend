# Security Controls

**Status:** Security control baseline
**Last updated:** 2026-10-06

## Purpose

Provide a practical control checklist for development, deployment, and operations.

## Identity and access

- [ ] Authentication is server-controlled.
- [ ] Passwords are securely hashed.
- [ ] Protected endpoints require authentication.
- [ ] Authorization is enforced server-side.
- [ ] Organization and project boundaries are enforced.
- [ ] Privileged actions require appropriate permissions.
- [ ] Authentication failures are rate-limited or otherwise protected from abuse.

## Application security

- [ ] All untrusted input is validated.
- [ ] Database queries are parameterized or safely generated by the ORM.
- [ ] CSRF protection is enabled where applicable.
- [ ] XSS protections are applied.
- [ ] Secure HTTP headers are configured appropriately.
- [ ] Error responses do not disclose secrets or unnecessary internals.
- [ ] File uploads/imports are restricted and safely parsed.

## Data security

- [ ] Sensitive data is classified.
- [ ] Data access follows least privilege.
- [ ] Sensitive values are protected in transit.
- [ ] Database backups are protected.
- [ ] Data retention requirements are defined.
- [ ] Exports are access-controlled and audited where appropriate.

## Infrastructure and secrets

- [ ] Production secrets are outside source control.
- [ ] Secrets are rotated according to risk.
- [ ] Production configuration is separated from development configuration.
- [ ] Dependencies are regularly reviewed and patched.
- [ ] Administrative access is restricted and auditable.

## Monitoring and response

- [ ] Security-relevant events are logged.
- [ ] Logs exclude passwords, tokens, and sensitive payloads.
- [ ] Logs are protected from unauthorized modification.
- [ ] Request/correlation identifiers support investigation.
- [ ] Incident response procedures are documented.
- [ ] Backups and restoration are tested.

## Verification

Controls should be verified through code review, automated tests, dependency scanning, configuration review, penetration testing where appropriate, and operational checks.

## Implementation note

Checkboxes represent control objectives. They should only be marked complete after evidence is available in the repository, deployment configuration, test results, or operational records.
