# Progress Monitoring

**Status:** User guide baseline  
**Last updated:** 2026-10-06

## Purpose

Explain how project progress is recorded and monitored.

## Reporting Period

Each progress update should have a defined:

- data date;
- reporting period;
- project;
- schedule/version;
- responsible user.

## Progress Workflow

```text
Set Data Date
     ↓
Collect Actuals
     ↓
Update Activities
     ↓
Record Physical Progress
     ↓
Update Forecast
     ↓
Calculate Performance
     ↓
Review Variance
```

## Types of Progress

Depending on the project, progress may be measured through:

- activity completion;
- physical percentage complete;
- quantities;
- milestones;
- earned value;
- schedule performance.

## Progress Validation

Before submission:

- actual starts should be supported;
- completed activities should have completion dates;
- progress should not exceed logical limits without explanation;
- the data date should be consistent;
- forecast dates should be reviewed.

## Performance Review

Compare current performance against:

- baseline;
- previous period;
- approved plan;
- forecast.

Investigate significant deviations.

## Status Workflow

A progress record may follow:

```text
Draft → Submitted → Reviewed/Approved → Historical
```

Actual statuses depend on implementation and project governance.
