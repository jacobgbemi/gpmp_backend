# Reporting

**Status:** User guide baseline  
**Last updated:** 2026-10-06

## Purpose

Explain how users generate and interpret project reports.

## Common Report Categories

Potential reports include:

- project status;
- schedule performance;
- cost performance;
- progress;
- variance;
- risk;
- resource;
- executive summary.

## Reporting Workflow

```text
Validate Data
    ↓
Select Reporting Period
    ↓
Select Report
    ↓
Apply Filters
    ↓
Generate
    ↓
Review
    ↓
Export/Share
```

## Reporting Period

Always verify the:

- data date;
- reporting period;
- schedule version;
- baseline version;
- cost period.

## Report Quality

A report should clearly communicate:

- current status;
- baseline/reference;
- variance;
- forecast;
- significant issues;
- required actions.

## Exporting

Where supported, reports may be exported to formats such as PDF, spreadsheet, or other application-supported formats.

Ensure exported information is shared only with authorized recipients.

## Report Validation

Before distributing a report:

- check project;
- check period;
- verify totals;
- inspect major variances;
- confirm assumptions;
- confirm the report version.

## Data Freshness

A report is only as reliable as its underlying data. Confirm that the latest approved schedule, cost, and progress information has been processed before relying on it for decisions.
