# Dashboards

**Status:** User guide baseline  
**Last updated:** 2026-10-06

## Purpose

Explain how users should use dashboards for project visibility and decision-making.

## Dashboard Principles

Dashboards should answer:

1. Where are we now?
2. Are we on plan?
3. What has changed?
4. What is at risk?
5. What requires action?

## Typical Dashboard Areas

A project-controls dashboard may present:

- schedule status;
- planned vs actual progress;
- milestone status;
- cost performance;
- forecast;
- variance;
- risks;
- key actions.

## Reading a Dashboard

Start with:

```text
Overall Status
     ↓
Major Variances
     ↓
Trend
     ↓
Root Cause
     ↓
Required Action
```

Do not interpret an indicator without checking its definition and reporting period.

## Filters

Where available, users may filter by:

- project;
- reporting period;
- WBS;
- discipline;
- cost category;
- status.

Always confirm active filters before interpreting numbers.

## Dashboard Data

Dashboards should be based on controlled project data. If a dashboard appears inconsistent with an approved report, verify:

- refresh status;
- data date;
- filters;
- schedule version;
- cost version;
- calculation rules.

## Decision-Making

Use dashboards as a decision-support tool, not as a substitute for reviewing source data when an important decision depends on a metric.
