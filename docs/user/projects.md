# Projects

**Status:** User guide baseline  
**Last updated:** 2026-10-06

## Purpose

Explain how users manage projects in GlintPM Private.

## Creating a Project

A project should normally have core information such as:

- project name;
- project identifier/code;
- description;
- client/owner;
- project type;
- planned start date;
- planned finish date;
- currency;
- organization/workspace.

Required fields depend on the implementation.

## Project Lifecycle

A typical lifecycle may be:

```text
Draft → Active → Completed
              ↘ Archived
```

The actual status model is determined by the application.

## Project Information

Maintain accurate project information because schedules, costs, progress, and reports may depend on it.

## Project Structure

A project may contain:

- work breakdown structure;
- activities;
- relationships;
- resources;
- budgets;
- actual costs;
- progress records;
- risks;
- reports.

## Managing Projects

Authorized users may be able to:

- view;
- create;
- update;
- archive;
- restore;
- manage project-related records.

Permissions should be respected for every project operation.

## Project Data Quality

Before reporting:

- confirm dates;
- confirm project status;
- verify currency;
- check schedule completeness;
- verify cost data;
- confirm the reporting period.
