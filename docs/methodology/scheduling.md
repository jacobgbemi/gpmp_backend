# Scheduling

**Status:** Methodology baseline  
**Last updated:** 2026-10-07

## Purpose

Scheduling converts project scope and execution strategy into a time-phased model that can be analyzed and controlled.

## Schedule Development

Typical steps:

1. Define WBS.
2. Develop activities.
3. Assign calendars.
4. Establish durations.
5. Link activities.
6. Add milestones.
7. Apply justified constraints.
8. Assign resources/costs where required.
9. Calculate the schedule.
10. Review critical path and float.
11. Validate schedule quality.
12. Submit for approval/baseline.

## Schedule Logic

Prefer logic-driven dates over excessive hard constraints.

Common relationship types:

- Finish-to-Start;
- Start-to-Start;
- Finish-to-Finish;
- Start-to-Finish.

## Critical Path

The critical path represents the chain of schedule logic that controls the project completion date under the scheduling model.

Critical-path analysis should consider:

- logic;
- calendars;
- constraints;
- float;
- actual progress;
- remaining duration;
- approved changes.

## Schedule Updates

Each update should establish a data date and record:

- actual starts;
- actual finishes;
- progress;
- remaining duration;
- forecast dates;
- logic changes;
- approved changes.

## Schedule Quality

Review for:

- missing predecessors/successors;
- excessive constraints;
- unrealistic durations;
- invalid dates;
- broken logic;
- negative/unexpected float;
- duplicate activity IDs;
- calendar inconsistencies.

The specific schedule-quality thresholds should be defined by project requirements.
