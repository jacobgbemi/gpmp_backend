# Change Control

**Status:** Methodology baseline  
**Last updated:** 2026-10-07

## Purpose

Change control ensures that changes to scope, cost, schedule, or other project parameters are evaluated and approved before becoming part of the controlled plan.

## Change Lifecycle

```text
Change Identified
      ↓
Logged
      ↓
Impact Assessed
      ↓
Reviewed
      ↓
Approved / Rejected
      ↓
Implemented
      ↓
Baseline / Forecast Updated
      ↓
Reported
```

## Change Assessment

Assess potential impact on:

- scope;
- schedule;
- cost;
- resources;
- quality;
- procurement;
- risk;
- contractual obligations.

## Change Record

A change record should typically include:

- identifier;
- description;
- reason;
- requester;
- date;
- impact assessment;
- cost impact;
- schedule impact;
- risk impact;
- approval;
- implementation status.

## Approved vs Pending Changes

Do not mix approved changes with unapproved assumptions in the controlled baseline.

Pending changes may be considered in forecast scenarios but should be clearly identified.

## Baseline Impact

If an approved change alters the contractual or approved plan, follow the project's baseline-change procedure.

## Auditability

Every material change should be traceable from:

```text
Request → Assessment → Approval → Implementation → Result
```
