# Baseline Management

**Status:** Methodology baseline  
**Last updated:** 2026-10-07

## Purpose

A baseline is an approved reference against which project performance is measured.

## Baseline Components

Depending on project requirements, the baseline may include:

- scope;
- schedule;
- milestones;
- planned progress;
- budget;
- time-phased cost;
- resource plan.

## Baseline Process

```text
Develop Plan
   ↓
Review
   ↓
Correct
   ↓
Approve
   ↓
Freeze Baseline
   ↓
Control Changes
```

## Baseline Rules

Once approved:

- changes should be controlled;
- original values should remain traceable;
- baseline revisions should have approval;
- changes should not silently overwrite history.

## Baseline Versions

Maintain version information such as:

- baseline ID;
- version;
- approval date;
- approver;
- effective period;
- reason for revision.

## Baseline vs Forecast

The baseline answers:

> What did we approve as the plan?

The forecast answers:

> Based on current information, what do we now expect?

These should not be confused.

## Rebaselining

Rebaselining should occur only under defined governance.

Typical triggers may include major approved scope changes or contractual changes.

Every rebaseline should preserve the previous baseline for historical analysis.
