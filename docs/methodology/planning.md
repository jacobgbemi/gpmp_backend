# Planning

**Status:** Methodology baseline  
**Last updated:** 2026-10-07

## Purpose

Planning defines what must be delivered, how it will be delivered, when it will occur, what resources are required, and how performance will be measured.

## Planning Inputs

Typical inputs include:

- scope;
- contract requirements;
- deliverables;
- milestones;
- work breakdown structure;
- execution strategy;
- project calendar;
- resource assumptions;
- cost estimates;
- risks;
- constraints.

## Planning Hierarchy

```text
Project
  ↓
WBS
  ↓
Control Accounts / Work Packages
  ↓
Activities
  ↓
Resources / Costs
```

## Planning Process

1. Understand scope.
2. Establish WBS.
3. Define deliverables.
4. Identify activities.
5. Establish logical relationships.
6. Estimate durations.
7. Assign resources and costs.
8. Identify constraints.
9. Develop the schedule.
10. Validate constructability/executability.
11. Establish baseline.
12. Begin controlled updates.

## Planning Quality

A good plan should be:

- complete;
- logically connected;
- measurable;
- resource-aware;
- cost-aware;
- time-phased;
- traceable to scope;
- suitable for progress measurement.

## Planning vs Scheduling

Planning establishes the execution strategy and control structure.

Scheduling translates that plan into time-phased activities, logic, dates, milestones, and forecasts.

They are related but not identical activities.
